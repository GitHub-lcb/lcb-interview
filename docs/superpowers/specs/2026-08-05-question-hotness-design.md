# 高频考点权重与突击背题设计

## 背景

经过产品方向讨论（office hours 六问收敛），确认核心定位：**给跳槽程序员一个"背什么"有确定性的题库工具**。

- 目标用户：1-2 周内要面试的跳槽程序员，短时间背题、刷题。
- 核心痛点：题库多而杂，不知道背什么、背的考不考。
- 差异化主轴：**内容贴合度**（高频考点权重 + 面经归类），决定"背什么"；答案呈现工程（分块、高亮、渐进展开）和记忆调度（间隔重复）为后续演进方向，本次不做。
- 商业模式：题库浏览、考点图谱免费（获客漏斗）；突击计划、模拟面试 + 复盘为付费点（本次只设计体验入口，不做支付）。
- 内容运营：公开面经语料 + AI 提取考点频次建立初始权重；用户面试回填 + 用户评论让权重与题目持续进化。

当前数据事实（本地库全量体检）：

- 6386 题全部 `AI_GENERATED` + `PUBLISHED`，无人工审核背书。
- 497 对重复标题，1178 题无标签（18.5%），172 处质量红旗，217 题答案无 Markdown 结构。
- 浏览量分布均匀（1199/1198/1195），无真实用户行为数据，个性化与内容有效性验证均无依据。
- 分类 46 个、标签 71 个，但缺少"考点（知识点）"层，题目之间无知识关联。

## 目标

- 建立 `分类 → 考点 → 题目` 三层知识结构，为背题提供目录。
- 从公开面经语料中提取考点频次，为每个考点与题目计算高频权重（面试被问概率），初始权重可区分、可解释。
- 用户面试后回填"今天被问了哪题"，与语料权重融合，让权重随真实需求进化。
- 提供"突击计划"：输入面试日期与岗位，输出按权重 + 考点依赖排序的每日背题清单。
- 数据闭环：AI 定期分析题目质量与用户反馈，输出题目升级建议（本次先设计管道，不实现自动改写）。

## 非目标

- 不做记忆调度（间隔重复 SRS）：突击场景时间窗口短，杠杆小，留待长留存产品形态。
- 不做答案呈现重构（分块/高亮/自测模式）：独立于数据层，后续基于同一考点结构演进。
- 不做支付系统与权限墙：本次免费/付费边界只体现在页面与接口规划上。
- 不保证"背了就考中"：权重是统计参考，页面必须保留免责说明。

## 数据模型设计

新增表（幂等迁移，不删除、不重建、不清空既有表）：

### `knowledge_point` 考点

| 字段 | 说明 |
|------|------|
| id | 主键 |
| category_id | 所属分类（46 分类之一） |
| name | 考点名称，如 "HashMap 原理" |
| slug | 唯一英文标识 |
| parent_id | 依赖的父考点（可空），用于突击计划排序 |
| hot_score | 高频权重分（0-100），语料 + 回填融合 |
| hot_score_source | 权重来源：`CORPUS` / `FEEDBACK` / `BLEND` |
| description | 考点说明（AI 生成 + 人工微调） |
| create_time / update_time / is_deleted | 通用字段 |

### `question_knowledge_point` 题目-考点关联

多对多。清洗阶段补齐 1178 道无标签题目时，同时补考点关联（标签是考点的一种粗粒度视角，不合并表）。

### `interview_source` 面经语料

| 字段 | 说明 |
|------|------|
| id | 主键 |
| source_url | 原文地址（去重键） |
| source_name | 来源站点 |
| company / position | AI 提取的公司、岗位（可空） |
| publish_date | 发布日期 |
| raw_content | 原文文本（仅本地处理，不对外展示） |
| status | `RAW`（已抓取）/ `EXTRACTED`（已提取考点）/ `FAILED` |
| extract_error | 提取失败原因 |
| create_time / update_time / is_deleted | 通用字段 |

### `knowledge_point_mention` 考点提及统计

| 字段 | 说明 |
|------|------|
| id | 主键 |
| interview_source_id | 语料 ID |
| knowledge_point_id | 考点 ID |
| mention_count | 该篇面经中被问次数（AI 提取） |
| context | 提及上下文片段（用于权重解释与人工核对） |

### `interview_feedback` 用户面试回填

| 字段 | 说明 |
|------|------|
| id | 主键 |
| user_id | 回填用户 |
| company / position | 面试公司、岗位（可空） |
| question_id | 被问到的题目（可空，匹配不上时只记考点） |
| knowledge_point_id | 命中考点 |
| interview_date | 面试日期 |
| create_time / update_time / is_deleted | 通用字段 |

回填入口放在题目详情页与突击计划页，提交后给积分/徽章激励（激励体系本次只保留埋点字段，不做发放）。

### `study_plan` / `study_plan_item` 突击计划

| 表 | 字段 | 说明 |
|----|------|------|
| study_plan | id, user_id, target_date, position, status, create_time... | 一次突击计划 |
| study_plan_item | id, plan_id, knowledge_point_id, question_id, scheduled_date, status(背/已背/已自测), feedback 标记 | 每日背题清单项 |

## 面经语料管道

### 抓取

- 源：牛客面经专栏、GitHub 面经仓库（如各类 `interview` 汇总仓库）、掘金/CSDN 面经文章。首期抓取 1000-2000 篇。
- 合规：只抓公开可见内容；仅提取考点统计，不复制原文对外展示；控制抓取频率；保留 source_url 与 source_name 用于署名与删除。
- 去重：`source_url` 唯一键 + 正文 simhash 去重。

### AI 提取

复用 `AiRuntimeConfigService` 的 OpenAI 兼容配置与 `AiGenerationRequestPolicy` 类限制策略。提示词要求输出：

- `company`、`position`：公司、岗位（识别不到则空）。
- `knowledgePoints`：`[{categoryId, name, mentionCount, context}]`，`categoryId` 必须来自现有 46 个分类；考点按 `(categoryId, name)` 先匹配后新增，新增为 `DRAFT` 状态。
- AI 必须为当前批次每个 `sourceId` 恰好返回一项；无技术考点时显式返回空数组，遗漏、重复或批次外 ID 均视为整批无效并重试。
- 输出 JSON 由策略类校验，失败标记 `FAILED` 并记录原因，不阻塞管道。

提取任务走批量任务框架（参考 `LotteryKl8` 批量生成与 `/api/admin/ai/batch` 的进度模型），支持断点续跑与失败重试。

## 高频权重计算

初始权重（语料主导）：

```
hot_score(考点) = 60% × 语料提及频次归一化 + 25% × 覆盖面经篇数归一化 + 15% × 题目数量因子（考点下题目覆盖度）
```

题目权重 = 所属考点权重 × 题目质量分（答案结构完整度 + 无质量红旗 + 人工核对抽检）。

权重进化（用户回填主导）：

- 每日定时任务：把 `interview_feedback` 按考点聚合为"真实被问频次"，与语料权重按 `8:2 → 4:6` 渐变融合（类快乐8校准思路：样本不足回退语料权重，样本充足后以反馈为准）。
- `hot_score_source` 标记当前主导来源，页面展示权重解释（"近 90 天被 132 份面经提及"或"被 28 位用户回填确认"）。

权重可区分性作为验收标准：前 20% 考点应集中 60% 以上被问频次；抽样 30 道题人工核对，权重排序与人工判断吻合度不低于 80%。

## 突击计划

- 输入：面试日期、目标岗位（可选）、每日可学习时长。
- 输出：按考点权重降序 + 依赖顺序（先父考点后子考点）生成题目清单，按剩余天数均分到每日配额。
- 每项状态：`背` → `已背` → `已自测`（自测后标记"没背住"的题目自动排入次日复背，形成简单复用，不做完整 SRS）。
- 计划结束日给出"完成度 + 薄弱考点"摘要，作为模拟面试（付费点）的入口。

## 前端设计

- 题库页增强：题目卡片显示高频权重分与命中考点标签；支持按权重排序。
- 考点图谱页（新增 `/review/knowledge` 或并入 `/routes`）：分类 → 考点 → 题目 三层浏览，考点按权重高亮，展示权重解释。
- 突击计划页（并入 `/study`）：创建计划、每日清单、打卡与复背。
- 题目详情页：面试回填入口（"今天被问到了这道题？"）+ 免责说明。
- 管理后台（并入 `/admin/dashboard` 或新增页）：语料管道进度、提取失败列表、考点合并/改权重、权重来源标记。

## 测试与验证

- 后端单测：考点关联清洗、权重计算（语料/回填/融合三态）、突击计划排序（权重 + 依赖）、面经提取 JSON 校验。
- MVP 验证（第一步，不碰产品代码）：爬取 1000 篇面经 → AI 提取 → 计算权重 → 输出权重分布报告（区分度指标 + 抽样 30 题人工核对）。分布平权则放弃语料路线，改 AI 先验 + 人工标注。
- 构建验证：`mvn test` + `npm run build`；数据库迁移幂等脚本。

## 实施顺序

1. **MVP 语料验证**：抓取 + AI 提取 + 权重分布报告（验证假设，1-2 天）。
2. **数据层**：建表 + 幂等迁移 + 考点清洗（AI 分批给 6386 题打考点 + 补标签）。
3. **权重管道**：初始权重计算 + 定时融合任务 + 管理后台语料页。
4. **突击计划**：计划生成算法 + `/study` 页面 + 回填入口。
5. **反馈闭环**：用户回填 → 权重进化 → AI 题目升级建议管道。
